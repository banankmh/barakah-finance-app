# بَرَكَة — الإصدار التجريبي المتصل بـ Supabase

## الوظائف المتاحة
- واجهة عربية متجاوبة RTL وقابلة للتثبيت كـ PWA على HTTPS.
- تسجيل الدخول وإنشاء الحساب بواسطة Supabase Auth.
- مساحات عمل مستقلة للمنزل والعمل ضمن قاعدة بيانات واحدة مع عزل الوصول بواسطة RLS.
- حسابات منفصلة حسب العملة (ILS / USD / JOD)، جهات، مشاريع، مشتريات، حركات، مستحقات.
- تقارير يومية وشهرية وسنوية، ملخصات ورسوم، تصدير CSV.
- مشاركة مساحة العمل بإضافة UID لمستخدم مسجل، بصلاحيات محرّر/مشاهد.

## التشغيل
1. لنشره: ارفع ملفات المجلد على مستودع GitHub **من دون بيانات مالية**، ثم Settings → Pages → Deploy from a branch → main / root.
2. في Supabase: Authentication → URL Configuration، أضف عنوان GitHub Pages الخاص بالموقع إلى Site URL / Redirect URLs عند الضرورة لتأكيد البريد.
3. افتح رابط الموقع، أنشئ الحساب وسجل الدخول (قد يتطلب تأكيد البريد).
4. اضغط «+ مساحة جديدة» ثم أنشئ «الشغل» و«المنزل» كلًّا على حدة.
5. أنشئ حسابًا ماليًا (مثل «صندوق شيكل») أولًا، ثم أضف الحركات.
6. ليستخدم الزوج التطبيق: يسجّل بحساب ثانٍ ويقرأ معرّفه (UID) من إعدادات مساحته الخاصة، ثم يضيفه مالك مساحة العمل من صفحة «الإعدادات والمشاركة» بالمعرّف. لا تشاركا كلمات المرور.

## الحماية
- `PUBLIC_KEY` في `app.js` هو مفتاح **Publishable** مصمم للظهور في الواجهة؛ لم نضع Service Role أو كلمة مرور.
- يُفرض الوصول للبيانات من PostgreSQL RLS على الخادم. لا ترفع ملفات CSV أو نسخًا احتياطية للمستودع.
- لا تعتمد على واجهة التطبيق وحدها لحماية البيانات: احتفظ بآلية RLS على قاعدة البيانات.

## حدود هذه النسخة
- التطبيق **يتطلب اتصالًا بالإنترنت لقراءة البيانات وحفظها**. الـService Worker يخزن ملفات الواجهة فقط، وليس لديه طابور عمليات مؤجل آمن. لا تدخِل حركات مالية عند انقطاع الإنترنت على أساس أنها ستُزامن تلقائيًا.
- لم تُختبر دورة تسجيل الدخول/الحفظ على جهازَي المستخدمين الحقيقيين بعد؛ لذا هذه نسخة تشغيل تجريبية وليست نظام إنتاج معتمد.
- الربح المحاسبي الحقيقي، التكلفة الموزونة للدفعات، التزامات مالكي الأموال، التحويلات الثنائية الذرية، وتسويات الديون من الواجهة ليست مكتملة بعد. لا تعتبر «الصافي» ربحًا.
- كل المصاريف على حدة؛ إدخال تفاصيل المشتريات **لا يسجل مصروفًا نقديًا تلقائيًا**، يجب تسجيل الدفع مرة واحدة في «الحركات» وربط سجل المشتريات به إن وجد.
- لا يوجد حذف قيود أو تعديلات للقيود المالية في الواجهة، لتقليل أخطاء الفترة التجريبية؛ التصحيح المحاسبي سيضاف بقيود معاكسة وسجل مراجعة.
- تتطلب الصلاحيات المتقدمة وأداء الجداول الكبيرة واختبار المزامنة مزيدًا من التطوير والاختبارات.

## ملفات التطبيق
- `index.html` واجهة التطبيق
- `style.css` التصميم
- `app.js` وظائف التطبيق والاتصال بـ Supabase
- `manifest.webmanifest` و `sw.js` و `icon.svg` لتثبيت PWA
